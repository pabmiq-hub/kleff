- Konektum registration-quotas.ts is the shared age/gender quota policy for public registration, eligibility and administration; compare known gender aliases and reclassify historical rows using birth dates/current event bands, without rewriting original participant data.
- Konektum public availability returns aggregate counts only; birth dates used to reclassify quotas stay server-side, and custom age fields derive from the event configuration rather than saved form options.
- Konektum Select placeholders and portaled item labels use stable element wrappers, not DOM prototype patches, so browser translators cannot detach React-owned nodes during selection.
- Konektum custom registration forms translate only known built-in display labels by event language; original option values and organizer-authored copy stay unchanged to preserve quotas, matching and participant history.
- Murder Mystery module ("Juegos") lives in src/lib/mm + src/components/mm with tables prefixed mm_; players never use Supabase Auth: all player reads/writes go through server functions that verify an HMAC player token, so is_killer and other characters' data never reach the browser.
- Juegos routes use the `actividades_` file prefix so they don't nest under the public /actividades page.
- Juegos character release, manual/random assignment and invitation registration use service-role-only SQL operations sharing a session lock, with a unique character index; SQL rechecks game limits and the UI uses pure eligibility rules so concurrent allocators cannot duplicate characters.
- Juegos act transitions use a shared murder-trigger rule in the engine and administration, so imported act keys and control modes cannot bypass the narrative event.
- Juegos theatrical readings are stored on the game and translated with its content; a shared server-side filter restricts player delivery by reader, act and reveal trigger to prevent early solution leaks.
- Juegos interaction plans are constructed only after HMAC validation; a service-role-only SQL function locks the session and commits acceptance, balances, uses, ownership and unlocks atomically to prevent replay and concurrent overspending.
- Juegos joint-action availability derives from participant-scoped request history, with a database insert trigger under the same session lock preventing reversed or repeated proposals; payments and item transfers remain repeatable.
- Juegos imports validate original avatar SVGs as self-contained XML and store them as image data URLs in the existing avatar_url field; original artwork takes precedence over DiceBear without adding schema or exposing markup inline.
- Juegos characters keep their order in the imported JSON (`sort_order`, see db/mm-assignment-order.sql): the release deals the killer first and then the cast in order, so games with min_players below the cast size always cover their essential (first) characters; games imported before the order existed stay random.
- Juegos evidences can ship their own `image_url` in the JSON; the import then fills only the missing ones with a Gemini-drawn SVG (`evidence-art.server.ts`, kind taken from `reveal_style`), sanitized like item art, and `mmGenerateEvidenceArt` can redraw them on demand.
- Juegos cover editing reuses the shared CMS ImagePicker and media upload pipeline; keep saving disabled during uploads so local files receive the same optimization and storage handling as other admin images.
- Juegos castle map (mm_locations, mm_location_features, mm_feature_reads; db/mm-map.sql) is filtered in map.server.ts: future-act places/features never leave the server and feature content/image travel only after a recorded read; pure rules and SVG validation live in map-art.ts, and the plan always falls back to a server-drawn SVG so pins line up.
- Juegos artwork gallery is admin-only via role-checked server functions; single-image regeneration scopes the selected row to its game, reuses existing Gemini generators and preserves the previous image on failure, so browsing art cannot leak player secrets or overwrite sibling drawings.
- Juegos player navigation uses shared pure grouping/voting-prompt rules and a dedicated navigation component; retain flat content IDs for unread tracking, and never mark hidden character subsections as read when opening the parent.
